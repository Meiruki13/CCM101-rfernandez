# Reflection

Honestly, this activity made cloud computing feel a lot less abstract to
me. Before this, "compute" and "storage" were just words from the textbook.
But once I was actually running commands on my own KillerCoda machine and
seeing real numbers come back — my own CPU, my own RAM, my own IP address —
it clicked in a way reading alone never really did.

If I had to pick the most important component, I'd say compute resources.
The module describes compute as what provides "the processing power
required to execute applications, perform calculations, and run operating
systems" (Chapter 2, p. 60), and honestly that tracks with how I see it too
— storage is just sitting there without something to actually use the data,
and a network has nothing to connect if there's nothing running on the
other end. Though I'll admit, the more I looked into it, the more I
realized these four components don't really work *without* each other.
Compute still needs somewhere to save its data and a way to be reached.

Linux's role in all this makes a lot more sense now too. The module points
out that Linux "remains the dominant operating system for cloud servers"
(Chapter 2, p. 69), which lines up with my own experience — every command
I ran this whole activity was Linux-based, no GUI, just the terminal.

The documentation part surprised me the most, actually. I didn't expect a
"write stuff down" step to matter this much until I read the LMS example in
the module — a university's system struggling during enrollment because of
limited hardware (Chapter 2, p. 61). That made it click: you can't fix or
scale something you never properly documented in the first place.

Skill-wise, I'd say I got more comfortable reading system specs from the
CLI, comparing AWS/Azure/GCP services side by side, and putting together my
first real architecture diagram in Draw.io. My GitHub portfolio is
starting to actually look like something now — two labs in, and it's
already showing more depth than just Lab 1 did on its own.
